# Domain checklist

## Common failure patterns

- Redesigning the entire platform during a review.
- Treating a diagram label as implementation evidence.
- Calling a style preference a critical defect.

## Review questions

- Findings identify a concrete mechanism and affected boundary.
- Recommendations preserve relevant constraints.
- The conclusion does not imply security certification.

## Worked boundary

Only a context diagram is available. State that transactions, permissions and failure behavior remain unreviewed.

This is authored engineering guidance, not a legal opinion, live observation or certification. Validate jurisdiction-specific, version-specific and environment-specific requirements from authoritative sources.
