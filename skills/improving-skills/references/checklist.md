# Domain checklist

## Common failure patterns

- Autonomously broadening permissions to pass a benchmark.
- Appending a new paragraph for every failure.
- Claiming self-improvement from a file rewrite alone.

## Review questions

- Each change maps to an observed or explicitly hypothesized failure.
- Previous safety boundaries are preserved.
- Evidence supports only the claims actually made.

## Worked boundary

A higher task score is achieved by ignoring approval requirements. Reject the change despite the score gain.

This is authored engineering guidance, not a legal opinion, live observation or certification. Validate jurisdiction-specific, version-specific and environment-specific requirements from authoritative sources.
