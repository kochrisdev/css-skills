# Domain checklist

## Common failure patterns

- Writing a sales pitch instead of a buildable brief.
- Treating stakeholder preference as user evidence.
- Using active-user counts without a time window.

## Review questions

- Each proposed feature supports a stated outcome.
- Non-goals and release exclusions are explicit.
- Acceptance criteria cover failure journeys as well as the happy path.

## Worked boundary

No user research exists. Label the problem hypothesis and propose validation rather than fabricated interviews.

This is authored engineering guidance, not a legal opinion, live observation or certification. Validate jurisdiction-specific, version-specific and environment-specific requirements from authoritative sources.
